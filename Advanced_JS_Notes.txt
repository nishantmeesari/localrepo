1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));

18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

--- Map ---

2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {

    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

===================================================================
23. SYMBOLS
===================================================================
A primitive data type that creates a UNIQUE, immutable value — even
two symbols with the same description are never equal.

    const sym1 = Symbol("id");
    const sym2 = Symbol("id");
    console.log(sym1 === sym2); // false (always unique)

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",
      [id]: 12345  // hidden/unique property key
    };

    console.log(user[id]); // 12345
    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

===================================================================
21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }

===================================================================
22. MAP & SET
===================================================================
--- Map ---
Key-value pairs, like an object, BUT:
- Keys can be ANY type (not just strings)
- Maintains insertion order
- Has a .size property directly
- Easier to iterate than objects

    const map = new Map();
    map.set("name", "Sam");
    map.set(1, "one");
    map.set(true, "yes");

    console.log(map.get("name")); // "Sam"
    console.log(map.size);        // 3

    for (const [key, value] of map) {
      console.log(key, value);
    }

--- Set ---
Collection of UNIQUE values only (no duplicates allowed).

    const set = new Set([1, 2, 2, 3, 3, 3]);
    console.log(set); // Set(3) {1, 2, 3}
    set.add(4);
    console.log(set.has(2)); // true
    set.delete(1);

Common use: quickly remove duplicates from an array:
    const unique = [...new Set([1, 1, 2, 2, 3])]; // [1, 2, 3]

23. SYMBOLS

A primitive data type that creates a UNIQUE, immutable value — even

Common use case: creating object property keys that won't collide with
other keys, even if someone else adds a property with the same name.

    const id = Symbol("id");
    const user = {
      name: "Sam",

    console.log(Object.keys(user)); // ["name"] - symbol keys are hidden
                                     // from normal enumeration

1. ERROR() CONSTRUCTOR
===================================================================
Built-in way to create error objects with a message and stack trace.

    const err = new Error("Something went wrong");
    console.log(err.message); // "Something went wrong"
    console.log(err.name);    // "Error"

Used with try/catch to handle exceptions gracefully:

    try {
      throw new Error("Invalid input");
    } catch (e) {
      console.log(e.message); // "Invalid input"
    }

Why it matters: gives you a name, message, and stack trace — much better
than throwing a plain string, since debugging tools can read the stack.

Custom errors (extend Error):

    class ValidationError extends Error {
      constructor(message) {
        super(message);
        this.name = "ValidationError";
      }
    }

===================================================================
2. JSON BASICS
===================================================================
JSON (JavaScript Object Notation) = text format for exchanging data.
Keys are always in double quotes. No functions, no undefined, no comments.

Two key methods:
    JSON.stringify(obj)   -> converts JS object to JSON string
    JSON.parse(jsonString) -> converts JSON string back to JS object

    const user = { name: "Sam", age: 25 };
    const json = JSON.stringify(user);   // '{"name":"Sam","age":25}'
    const back = JSON.parse(json);       // { name: "Sam", age: 25 }

Why it matters: APIs send/receive data as JSON. You always parse the
response body before using it in JS.

===================================================================
3. APIs, REQUESTS & RESPONSES
===================================================================
API (Application Programming Interface) = a way for programs to talk
to each other, usually over HTTP.

Client = the one requesting data (browser/app)
Server = the one providing data (backend)

A Request has:
- URL (endpoint)
- Method (GET, POST, PUT, DELETE)
- Headers (metadata, e.g. Content-Type)
- Body (data sent, for POST/PUT)

A Response has:
- Status code (200 OK, 404 Not Found, 500 Server Error)
- Headers
- Body (usually JSON)

Endpoint example: https://api.example.com/users/5
- "/users" = resource
- "/5" = specific id

===================================================================
4. FETCHING DATA (.then() vs async/await)
===================================================================
fetch() returns a Promise that resolves to a Response object.

--- Using .then() ---
    fetch("https://api.example.com/data")
      .then(response => response.json())   // parse body as JSON
      .then(data => console.log(data))
      .catch(error => console.log("Error:", error));

--- Using async/await (cleaner, reads top-to-bottom) ---
    async function getData() {
      try {
        const response = await fetch("https://api.example.com/data");
        const data = await response.json();
        console.log(data);
      } catch (error) {
        console.log("Error:", error);
      }
    }

Key point: `await` only works inside an `async` function. It pauses
execution until the Promise settles, without blocking the rest of the app.

response.ok -> boolean, true if status is 200-299. Good for checking
success before trying to parse the body:

    if (!response.ok) throw new Error("Request failed");

===================================================================
5. PROMISES
===================================================================
A Promise represents a value that will be available now, later, or never.

Three states:
- pending   -> initial state
- fulfilled -> operation succeeded (resolve called)
- rejected  -> operation failed (reject called)

Creating a promise manually:

    const myPromise = new Promise((resolve, reject) => {
      const success = true;
      if (success) {
        resolve("Data loaded");
      } else {
        reject("Failed to load");
      }
    });

    myPromise
      .then(result => console.log(result))
      .catch(error => console.log(error));

Why they exist: solve the problem of nested callbacks (see Callback Hell)
by allowing chaining instead of nesting.

===================================================================
6. HANDLING REJECTED PROMISES & PROMISE.ALL
===================================================================
--- Handling rejection ---
Always attach .catch() (or try/catch with async/await) or errors go
unhandled silently in the console.

    fetch(url)
      .then(res => res.json())
      .catch(err => console.log("Failed:", err));

--- Promise.all() ---
Runs multiple promises in PARALLEL and waits for ALL to finish.
If even ONE rejects, the whole thing rejects immediately.

    const p1 = fetch(url1).then(res => res.json());
    const p2 = fetch(url2).then(res => res.json());

    Promise.all([p1, p2])
      .then(([data1, data2]) => {
        console.log(data1, data2);
      })
      .catch(err => console.log("One of them failed:", err));

Use case: loading multiple independent resources at once (faster than
awaiting them one by one in sequence).

Note: Promise.allSettled() is a cousin — it waits for all promises
regardless of success/failure and gives you the status of each (doesn't
fail fast like Promise.all).

===================================================================
7. CALLBACK HELL
===================================================================
Happens when callbacks are nested inside callbacks inside callbacks —
hard to read, hard to debug ("pyramid of doom").

    getUser(id, function(user) {
      getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
          console.log(comments);
          // deeply nested, hard to maintain
        });
      });
    });

Fix: use Promises (chaining with .then()) or async/await to flatten
the structure and make it read top-to-bottom.

--- SOLUTION 1: Promise chaining ---
Instead of nesting callbacks, each .then() returns a promise that the
next .then() waits on. Flat structure instead of a pyramid.

    getUser(id)
      .then(user => getPosts(user.id))
      .then(posts => getComments(posts[0].id))
      .then(comments => {
        console.log(comments);
      })
      .catch(error => {
        console.log("Something failed:", error); // ONE catch for all steps
      });

(This assumes getUser, getPosts, getComments each return a Promise
instead of taking a callback.)

--- SOLUTION 2: async/await (cleanest) ---
Reads almost like synchronous code, top to bottom.

    async function loadComments(id) {
      try {
        const user = await getUser(id);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
      } catch (error) {
        console.log("Something failed:", error); // ONE try/catch for all steps
      }
    }

    loadComments(id);

Why this fixes it: each step is on its own line instead of nested
inside the previous one, error handling is centralized (one .catch or
one try/catch) instead of needing a check inside every callback, and
the code reads in the actual order things happen.

===================================================================
8. OPTIONAL CHAINING & NULLISH COALESCING
===================================================================
--- Optional Chaining (?.) ---
Safely access nested properties without manually checking each level
for null/undefined. Returns undefined instead of throwing an error.

    const user = { profile: { name: "Sam" } };
    console.log(user.profile?.name);     // "Sam"
    console.log(user.address?.city);     // undefined (no error)

Works with function calls too:
    user.greet?.();  // only calls greet if it exists

--- Nullish Coalescing (??) ---
Returns the right-hand value ONLY if the left side is null or undefined
(NOT for other falsy values like 0, "", false).

    const count = 0;
    console.log(count ?? 10);   // 0  (0 is not null/undefined)
    console.log(count || 10);   // 10 (|| treats 0 as falsy — different!)

    const name = null;
    console.log(name ?? "Guest"); // "Guest"

Key difference from || : ?? only cares about null/undefined, || cares
about ALL falsy values (0, "", NaN, false, null, undefined).

===================================================================
9. CONSTRUCTOR FUNCTIONS
===================================================================
A regular function used with `new` to create objects with shared structure.

    function Person(name, age) {
      this.name = name;
      this.age = age;
    }

    const p1 = new Person("Sam", 25);
    console.log(p1.name); // "Sam"

What `new` does:
1. Creates a new empty object
2. Sets `this` to point to that object
3. Links the object's prototype to Person.prototype
4. Returns the object automatically (unless you return another object)

Methods should go on the prototype (not inside the constructor) so all
instances SHARE one copy instead of each getting its own:

    Person.prototype.greet = function() {
      console.log(`Hi, I'm ${this.name}`);
    };

Classes (ES6) are syntactic sugar over this same pattern.

===================================================================
10. .call() AND .apply()
===================================================================
Both let you invoke a function with an explicit `this` value.

--- .call() ---
Arguments passed individually.

    function greet(greeting) {
      console.log(`${greeting}, ${this.name}`);
    }
    const user = { name: "Sam" };
    greet.call(user, "Hello"); // "Hello, Sam"

--- .apply() ---
Same as call, but arguments passed as an ARRAY.

    greet.apply(user, ["Hello"]); // "Hello, Sam"

Common use case (old-style): borrowing methods from another object, or
using apply to spread an array into function arguments (less needed now
that spread operator ... exists).

Memory trick: Call = Comma-separated args. Apply = Array of args.

(bind() is the related third method — returns a NEW function with `this`
permanently set, instead of calling it immediately.)

===================================================================
11. INHERITANCE
===================================================================
Lets one object/class reuse properties and methods from another.

--- With constructor functions ---
    function Animal(name) {
      this.name = name;
    }
    Animal.prototype.speak = function() {
      console.log(`${this.name} makes a sound`);
    };

    function Dog(name) {
      Animal.call(this, name);  // call parent constructor
    }
    Dog.prototype = Object.create(Animal.prototype); // link prototypes
    Dog.prototype.constructor = Dog;

    const d = new Dog("Rex");
    d.speak(); // "Rex makes a sound"

--- With classes (cleaner syntax, same mechanism underneath) ---
    class Animal {
      constructor(name) {
        this.name = name;
      }
      speak() {
        console.log(`${this.name} makes a sound`);
      }
    }

    class Dog extends Animal {
      constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
      }
    }

    const d = new Dog("Rex", "Labrador");
    d.speak(); // "Rex makes a sound"

===================================================================
12. POLYMORPHISM
===================================================================
"Many forms" — a child class can override a parent's method to give
its own behavior, while still being usable through the same interface.

    class Animal {
      speak() {
        console.log("Some generic sound");
      }
    }

    class Dog extends Animal {
      speak() {
        console.log("Woof!");
      }
    }

    class Cat extends Animal {
      speak() {
        console.log("Meow!");
      }
    }

    const animals = [new Dog(), new Cat()];
    animals.forEach(a => a.speak());
    // "Woof!"
    // "Meow!"

Why it matters: you can treat different objects the same way (call
.speak() on all of them) and each responds according to its own type.

===================================================================
13. STATIC METHODS & PROPERTIES
===================================================================
Belong to the CLASS itself, not to instances. Called directly on the
class, not on objects created from it. Useful for utility/helper functions
related to the class but not tied to a specific instance.

    class MathHelper {
      static PI = 3.14159;

      static square(x) {
        return x * x;
      }
    }

    console.log(MathHelper.square(4)); // 16
    console.log(MathHelper.PI);        // 3.14159

    const m = new MathHelper();
    m.square(4); // ERROR - not available on instances

===================================================================
14. PRIVATE FIELDS
===================================================================
Fields that can only be accessed INSIDE the class, not from outside.
Declared with a # prefix (ES2022+).

    class BankAccount {
      #balance = 0;   // private field

      deposit(amount) {
        this.#balance += amount;
      }

      getBalance() {
        return this.#balance;
      }
    }

    const acc = new BankAccount();
    acc.deposit(100);
    console.log(acc.getBalance()); // 100
    console.log(acc.#balance);     // SyntaxError - can't access outside

Why it matters: enforces encapsulation — outside code can't directly
mess with internal state; it must go through defined methods.

===================================================================
15. GETTERS & SETTERS
===================================================================
Let you define methods that behave like properties — control how a
value is read (get) or written (set), often used with private fields.

    class Person {
      #age = 0;

      get age() {
        return this.#age;
      }

      set age(value) {
        if (value < 0) {
          console.log("Age can't be negative");
          return;
        }
        this.#age = value;
      }
    }

    const p = new Person();
    p.age = 25;        // uses setter
    console.log(p.age); // 25 (uses getter, no parentheses needed!)
    p.age = -5;         // "Age can't be negative"

Why it matters: lets you add validation/logic while keeping the clean
syntax of accessing it like a normal property (no function call parens).

===================================================================
16. CLOSURES
===================================================================
A function "remembers" the variables from its outer scope even after
the outer function has finished executing.

    function makeCounter() {
      let count = 0;
      return function() {
        count++;
        return count;
      };
    }

    const counter = makeCounter();
    console.log(counter()); // 1
    console.log(counter()); // 2
    console.log(counter()); // 3

`count` isn't reset each time because the inner function keeps a
reference to it — it's "closed over."

Why it matters: used for data privacy (like private variables before
# fields existed), and is the foundation for currying, debouncing,
throttling, and many patterns.

===================================================================
17. RECURSION
===================================================================
A function that calls ITSELF to solve a smaller version of the same
problem, until it hits a base case (stopping condition).

    function factorial(n) {
      if (n <= 1) return 1;       // base case
      return n * factorial(n - 1); // recursive case
    }

    console.log(factorial(5)); // 120

Every recursive function needs:
1. A base case (stops the recursion)
2. A recursive case (calls itself with a smaller/simpler input)

Without a base case -> infinite recursion -> "Maximum call stack
size exceeded" error.

Example - sum all numbers in an array:

    function sumArray(arr) {
      if (arr.length === 0) return 0;
      return arr[0] + sumArray(arr.slice(1));
    }

===================================================================
18. CURRYING
===================================================================
Transforming a function that takes multiple arguments into a series
of functions that each take ONE argument.

    // Normal function
    function add(a, b, c) {
      return a + b + c;
    }

    // Curried version
    function curriedAdd(a) {
      return function(b) {
        return function(c) {
          return a + b + c;
        };
      };
    }

    console.log(curriedAdd(1)(2)(3)); // 6

Arrow function shorthand:
    const curriedAdd = a => b => c => a + b + c;

Why it matters: allows partial application — you can "pre-fill" some
arguments and reuse the resulting function later.

    const add5 = curriedAdd(5);
    console.log(add5(2)(3)); // 10

===================================================================
19. THROTTLING
===================================================================
Ensures a function runs AT MOST once every X milliseconds, no matter
how many times it's triggered. Extra calls in between are ignored.

    function throttle(fn, delay) {
      let lastCall = 0;
      return function(...args) {
        const now = Date.now();
        if (now - lastCall >= delay) {
          lastCall = now;
          fn(...args);
        }
      };
    }

    window.addEventListener("scroll", throttle(() => {
      console.log("Scroll event handled");
    }, 1000));

Use case: scroll events, resize events, button spam-click prevention —
anything that fires rapidly but you only want to react periodically.

===================================================================
20. DEBOUNCING
===================================================================
Ensures a function only runs AFTER a certain amount of time has passed
since the LAST time it was called. Resets the timer on every call.

    function debounce(fn, delay) {
      let timer;
      return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => {
          fn(...args);
        }, delay);
      };
    }

    const searchInput = document.getElementById("search");
    searchInput.addEventListener("input", debounce((e) => {
      console.log("Searching for:", e.target.value);
    }, 500));

Use case: search-as-you-type (wait until user stops typing), form
validation, resize event that should only fire once user stops resizing.

Throttle vs Debounce (important distinction):
- Throttle: runs at a steady regular interval WHILE events keep firing.
- Debounce: waits for a pause/silence before running ONCE.

21. GENERATORS
===================================================================
Special functions that can PAUSE and RESUME execution. Declared with
`function*` and use `yield` to pause and return a value.

    function* countUp() {
      yield 1;
      yield 2;
      yield 3;
    }

    const gen = countUp();
    console.log(gen.next()); // { value: 1, done: false }
    console.log(gen.next()); // { value: 2, done: false }
    console.log(gen.next()); // { value: 3, done: false }
    console.log(gen.next()); // { value: undefined, done: true }

Can be looped with for...of:
    for (const num of countUp()) {
      console.log(num); // 1, 2, 3
    }

Why it matters: useful for lazy evaluation (generating values on demand
instead of all at once), infinite sequences, and custom iterators.

Infinite generator example:
    function* idGenerator() {
      let id = 1;
      while (true) {
        yield id++;
      }
    }
